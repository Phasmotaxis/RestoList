\section{Live Panel Sabotage Defense Kernel}

\subsection{Defense-in-Depth Exception Handling}
During live academic capstone examinations, evaluators frequently inject unexpected runtime anomalies, modify controller logic, or trigger division-by-zero faults to test system resiliency. EIMS introduces the \texttt{App\textbackslash Core\textbackslash ErrorHandler} defense kernel, which registers a three-tier interception mechanism:
\begin{enumerate}
    \item \texttt{set\_error\_handler}: Intercepts non-fatal PHP warnings, notices, and deprecations, elevating them directly to typed \texttt{ErrorException} instances.
    \item \texttt{set\_exception\_handler}: Catches all uncaught \texttt{Throwable} implementations across the request lifecycle.
    \item \texttt{register\_shutdown\_function}: Inspects \texttt{error\_get\_last()} on script termination to trap unrecoverable parse and memory allocation disruptions.
\end{enumerate}

\subsection{High-Contrast Visual Diagnostic Console}
When an anomaly is trapped, the kernel intercepts the output buffer and renders a standalone, zero-dependency diagnostic console:
\begin{itemize}
    \item Exact error classification, message, and HTTP 500 status code.
    \item Full stack trace with contextual source code highlighting (five preceding and subsequent lines surrounding the fault).
    \item High-contrast dark theme ($>7:1$ WCAG AAA contrast ratio) formatted in monospace typography.
    \item Complete isolation from external stylesheets, guaranteeing the diagnostic screen renders even if static web assets are deleted or corrupted.
\end{itemize}
